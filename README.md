# Novel Translator — แปลนิยายจีน → ไทย ด้วย AI

เว็บแปลนิยายจีนเป็นไทยด้วย Claude โดยเน้นให้คำแปล **สม่ำเสมอทั้งเรื่อง**:
คลังคำแยกหมวด + ชื่อแฝง, ตารางสรรพนามแบบ "ใครพูดกับใคร" ที่เปลี่ยนตามช่วงตอนได้, สรุปตอนก่อนหน้า และ style preset ที่เลือกได้
AI ไม่ได้ "จำ" เอง — ทุกอย่างเก็บใน SQLite แล้วระบบเลือกเฉพาะส่วนที่เกี่ยวกับตอนนั้นใส่ใน prompt

## ขั้นตอนต่อหนึ่งตอน

1. **นำเข้า** — วางข้อความหรืออัปโหลด .txt (ถ้ามีหัวข้อ `第N章` หลายตอนในไฟล์เดียว จะแยกตอนให้อัตโนมัติ)
2. **① สกัดคำใหม่** (`SMALL_MODEL`, ค่าเริ่มต้น Haiku 4.5) — AI เสนอคำเฉพาะที่ยังไม่มีในคลัง สถานะ `pending`
3. **รีวิวคำใหม่** — แก้คำแปล/หมวด แล้วอนุมัติ, ทิ้ง หรือรวมเป็นชื่อแฝงของคำเดิม (คำ pending จะไม่ถูกใส่ใน prompt)
4. **② แปล** (`TRANSLATE_MODEL`, ค่าเริ่มต้น Sonnet 5.5; เลือก Opus 5.5 ได้ในหน้าแปล)
   - ตัดเป็นช่วงตามย่อหน้า ~1,800–2,500 อักษรจีน และส่ง 2 ย่อหน้าท้ายของช่วงก่อน (พร้อมคำแปล) ไปด้วยเพื่อให้รอยต่อลื่น
   - จับคำในคลังด้วย string matching แบบ **longest match first** (รวมชื่อแฝง)
   - prompt = กฎพื้นฐาน + preset + few-shot *(cache)* → คลังคำ/ตัวละคร/ตารางสรรพนาม/สรุปตอนก่อน เฉพาะที่เจอในตอนนี้ *(cache ข้ามช่วงในตอนเดียวกัน)* → ย่อหน้าที่ต้องแปล
   - ย่อหน้ามีหมายเลขกำกับ จึงแสดงผลเทียบ จีน–ไทย รายย่อหน้าได้ และแก้ไขมือรายย่อหน้าได้ (ย่อหน้าที่โมเดลข้ามจะถูกขอแปลซ้ำอัตโนมัติ 1 ครั้ง)
   - ทุกครั้งที่แปลใหม่จะเก็บเป็นเวอร์ชันใหม่
5. **ตรวจและอัปเดต** (อัตโนมัติหลังแปล)
   - flag ย่อหน้าที่มีคำในคลังแต่คำแปลไทยไม่ตรง (ชื่อแฝงจะถูกตรวจเฉพาะเมื่อกำหนดคำแปลของชื่อแฝงไว้)
   - สรุปตอนสั้นๆ เก็บไว้ใช้เป็นบริบทตอนถัดไป
   - AI เสนอแถวใหม่ในตารางสรรพนาม (เช่น ความสัมพันธ์เปลี่ยน) → ไปอนุมัติ/แก้ที่หน้า "ตัวละคร & สรรพนาม"

## โหมดแปลผ่านแชท Claude (ไม่เสียค่า API)
ตั้งที่ "ตั้งค่านิยาย → วิธีแปล" ให้เป็น **คัดลอกไปแปลในแชท Claude / Project** เว็บจะยังดูแลคลังคำ สรรพนาม สรุปตอน และตัวตรวจให้เหมือนเดิม แต่การเรียก AI ทำผ่านแชทแทน (ไม่ต้องมี `ANTHROPIC_API_KEY`)

1. **คัดลอก prompt สกัดคำ** → วางในแชท Claude → คัดลอกคำตอบ (JSON) กลับมาวาง → **นำเข้าคำ** → ไปอนุมัติที่หน้ารีวิวคำใหม่
2. **คัดลอก prompt แปล** → วางในแชท → คัดลอกคำตอบทั้งหมดกลับมาวาง → **นำเข้าคำแปล**
   - prompt มีแนวการแปล + คลังคำเฉพาะที่เจอในตอน + ตารางสรรพนาม ณ ตอนนั้น + เรื่องย่อตอนก่อน + ต้นฉบับใส่เลขย่อหน้า จึงไม่ต้องอัปโหลดไฟล์ใดๆ เข้า Project
   - Claude จะต่อท้ายด้วย `=== สรุป ===` และ `=== สรรพนาม ===` เว็บแยกเก็บสรุปและสร้างข้อเสนอสรรพนาม (รออนุมัติ) ให้เอง
   - ถ้าคำตอบถูกตัดกลางทาง: พิมพ์ "ต่อ" ในแชท แล้ววางท่อนถัดไปโดยติ๊ก **เติมต่อจากคำแปลล่าสุด** หรือกด **คัดลอก prompt เฉพาะย่อหน้าที่ขาด**
   - ตัวตรวจคำไม่ตรงคลังทำงานในเว็บ ไม่ใช้ AI

ถ้าเข้าเว็บผ่าน `http://` (เช่น IP ของ NAS) เบราว์เซอร์อาจไม่ยอมให้คัดลอกอัตโนมัติ ให้เปิด "ดู/คัดลอก prompt เอง" แล้วคัดลอกจากกล่องข้อความแทน

## ตารางสรรพนาม
เก็บเป็นคู่ ผู้พูด → ผู้ฟัง พร้อม `ตั้งแต่ตอน` — ตอนที่แปลจะใช้แถวล่าสุดที่มีผล ณ ตอนนั้น
ตัวอย่าง: หลินเฟิง → ซูเหยา: "ข้า / ศิษย์น้อง" ตั้งแต่ตอน 1, แล้วเพิ่มแถว "พี่ / เหยาเอ๋อร์" ตั้งแต่ตอน 120
คู่ที่ไม่มีในตาราง ใช้ "แทนตัวเองทั่วไป" ของตัวละครนั้น

## รันบนเครื่อง (dev)

```bash
npm install
cp .env.example .env.local   # ใส่ ANTHROPIC_API_KEY
npm run dev                  # http://localhost:3000
npm test                     # unit tests (glossary matching, chunking, pronouns, checker)
```

ฐานข้อมูลอยู่ที่ `data/novel.db` (สร้างและ migrate อัตโนมัติตอนเริ่ม พร้อม preset ตั้งต้น 3 แบบ)
แก้ schema ที่ `src/db/schema.ts` แล้วรัน `npm run db:generate` เพื่อสร้างไฟล์ migration ใหม่ใน `drizzle/`

## รันบน NAS ด้วย Docker

```bash
echo "ANTHROPIC_API_KEY=sk-ant-..." > .env
docker compose up -d --build
```

- ข้อมูล SQLite อยู่ใน `./data` (mount เข้า container) ไม่หายตอน rebuild — สำรองโฟลเดอร์นี้เป็นระยะ
- อัปเดต: `git pull && docker compose up -d --build`
- เข้าจากนอกบ้านด้วย Tailscale (แนะนำ) หรือ Cloudflare Tunnel — **อย่าเปิด port router ตรงๆ** แอปนี้ยังไม่มีระบบล็อกอิน

## ตัวแปร environment

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | จำเป็นสำหรับโหมด API (โหมดแชทไม่ต้องใช้) |
| `TRANSLATE_MODEL` | `claude-sonnet-5-5` | โมเดลแปล |
| `SMALL_MODEL` | `claude-haiku-4-5` | โมเดลสกัดคำ / สรุป / เสนอสรรพนาม |
| `TRANSLATE_EFFORT` | `medium` | effort ของโมเดลแปล (`low`/`medium`/`high`) |
| `ANTHROPIC_FALLBACKS` | เปิด | ตั้ง `off` เพื่อปิด server-side refusal fallback |
| `CHUNK_TARGET` / `CHUNK_MAX` | `1800` / `2500` | ขนาดช่วง (อักษรจีน) |
| `SUMMARY_CHAPTERS` | `3` | จำนวนสรุปตอนก่อนหน้าที่ใส่ใน prompt |
| `DATABASE_PATH` | `./data/novel.db` | ไฟล์ SQLite |

## ต้นทุน
- ทุกการเรียก API บันทึก token (input / cache read / cache write / output) — ดูยอดรวมโดยประมาณที่หน้า **ค่าใช้จ่าย API**
- ส่วน preset และบริบทของตอนถูก prompt-cache ไว้ จึงจ่ายเต็มราคาแค่ช่วงแรกของแต่ละตอน
- งานเล็ก (สกัดคำ, สรุป) ใช้ Haiku; ใช้โมเดลใหญ่เฉพาะตอนแปล

## โครงสร้างโค้ด

```
src/db/schema.ts            ตาราง (Drizzle + SQLite)
src/lib/glossary.ts         GlossaryMatcher — longest-match-first + aliases
src/lib/text.ts             แยกย่อหน้า / ตัดช่วง / parse ผลลัพธ์ / แยกตอนตอนนำเข้า
src/lib/pronouns.ts         เลือกแถวสรรพนามตาม valid_from_chapter
src/lib/prompt.ts           ประกอบ prompt
src/lib/novel-context.ts    ดึงคลังคำ/ตัวละคร/สรรพนาม/สรุป ที่เกี่ยวกับตอนนั้น
src/lib/pipeline/           extract.ts, translate.ts, review.ts (API) + apply.ts (บันทึกผล ใช้ร่วมกับโหมดแชท)
src/lib/manual.ts           สร้าง prompt และอ่านคำตอบสำหรับโหมดแชท
src/app/api/chapters/[id]/  extract, translate (stream ความคืบหน้าแบบ NDJSON), review
src/app/actions.ts          server actions สำหรับ CRUD
```
